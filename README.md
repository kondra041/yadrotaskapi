# Yadro Task API

Веб-приложение для загрузки и отображения пользователей из внешнего API с поддержкой пагинации. Разработчик (исполнитель): Кондрюков Д.С.

## 1. Стек технологий

- Backend: Spring Boot 3 / Java 21
- Frontend: React (Vite)
- Database: PostgreSQL 16
- Docker / Docker Compose

## 2. Запуск проекта

#### Клонирование репозитория

```bash
git clone https://github.com/kondra041/yadrotaskapi.git
cd yadrotaskapi
```

#### Сборка и запуск всех сервисов (Docker)

```bash
docker-compose up
```

## 3. Доступ к сервисам

#### - Backend
http://localhost:8080
http://localhost:8080/swagger-ui.html (swagger API)

#### - Frontend
http://localhost:3000

#### - PostgreSQL
- **host:** localhost  
- **port:** 5434  
- **user:** postgres  
- **password:** postgres  
- **database:** yadro

## 4. Обоснование выбора стека технологий

В качестве backend-основы выбрана Java 21 и Spring Boot, так как это современная LTS-версия Java, которая обеспечивает стабильность, высокую производительность и поддержку актуальных возможностей языка. Spring Boot был выбран благодаря своей способности быстро разрабатывать REST API без избыточной конфигурации, а также встроенной поддержке работы с базой данных через Spring Data JPA, удобной интеграции с внешними API и развитой экосистеме тестирования с JUnit и Mockito, что является частью задания. Это позволило эффективно реализовать бизнес-логику в виде многослойной (контроллер, сервис, репозиторий) архитектруы, загрузку данных из внешнего API и работу с большим объёмом пользователей.

В качестве базы данных использую PostgreSQL, поскольку надёжная и производительная реляционная СУБД. Подходит для хранения структурированных данных и работы с большими объёмами информации. На своем опыте отмечу стабильную интеграцию со Spring Boot, обсеспечивающую удобную рабту с индексами, запросами и транзакциями.

Frontend реализован на React с использованием Vite, так как React предоставляет удобный компонентный подход в разработке интерфейса и хорошо подходит для отображения динамических таблиц и страниц пользователей. Vite выбран благодаря быстрой сборке, лёгкой конфигурации и поддержке функции hot-reload для ускорения и удобства процесса разработки и отладки. Для UI-компонентов дополнительно использую shadcn/ui - т.к он предоставляет готовые, доступные и "легко кастомизируемые" компоненты на основе Radix UI и Tailwind CSS. Это позволяет ускорить разработку простого, но отзывчивого и стабильного интерфейса, сохранить единый стиль приложения и при этом не потерять гибкость в дизайне и доработке компонентов.

Подводя итог, с помощью выбранного стека технологий разработано простое, но масштабируемое клиент-серверное приложение, которое удобно тестировать и легко разворачивать в Docker-окружении, обеспечивая воспроизводимость и удобство запуска данного проекта.
